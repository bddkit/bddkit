# `bddkit init`

Loaded on demand; the root `CLAUDE.md` holds the invariants that apply everywhere.

- **`init` asks nothing a flag already answered, and preselects nothing.** Every `Select`/`MultiSelect` is built WITHOUT `.default()`: dialoguer then starts with nothing highlighted and Enter does nothing until a move, which is the epic's no-preselected-answer decision (a `.default(0)` is a preselected yes). Esc on a list is `None`; Ctrl-C is different: on Unix `console` hides the cursor, then RAISES SIGINT instead of returning an error, so `command` holds it with `tokio::signal::ctrl_c` (`exit_on_ctrl_c`, installed only when prompting) — without that handler the process dies by signal with the cursor hidden — and the read comes back `Interrupted`, which `answered` maps to `None` like Esc; both end in exit 130, cursor restored, nothing written (`WRITING` only changes the message once `apply` started). dialoguer's `Input` has no Esc at all; both ways in go through `cancel()`, which prints once. Verified in a pty, not by a test. Values `init` writes go through `literal()`: the config text is `$`-expanded BEFORE it is parsed, so a typed `$` becomes `$$` and only `${NAME}` is kept as a reference. `--layer user` is passed to `install` as the explicit label, never the auto-pick (which would choose `/etc/bddkit` when only it exists), except under `--bddkit-dir`. The existing-config check runs again right before the write and also refuses the `bddkit.yaml`/`bddkit.yml` pair. The config is built as `serde_yaml_ng` values, one top-level block per key under a comment, so a DSN or URL is quoted by the serializer and never by string formatting; `resources.api` is always written, `{}` when there is no API, because `Resources::api` is required. The write is a temporary name in the same directory plus a rename (`resource::write_atomically` needs an existing file, `init` creates one). A work tree is any ancestor holding `.git` as a directory OR a file, because a linked worktree has a file. `init` writes the `telemetry` key and asks the question through `telemetry::ask_yes_no` (text: `telemetry::QUESTION_TEXT`), the same prompt `run` and `doctor` use; its payload is built in `command` after `apply`, only after a yes, and only if the layers above the key it just wrote still say on (see the telemetry gotchas). The echo fixture is `shared` and has a reset, so `doctor` refuses it under `concurrency` 8; its `init` tests pass `--parallel false`.
